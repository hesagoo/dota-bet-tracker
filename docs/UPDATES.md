# Система обновлений Dota Bet Tracker

## Как это работает (коротко)
1. Вы получаете от меня новую версию проекта и собираете её: `build_exe.bat`.
2. Запускаете `make_release.bat` — он делает папку `release\<версия>\` с файлами: `latest.json`, полный пакет и **дельта-пакет** (только изменённые файлы).
3. Загружаете эти файлы в **GitHub Release** (один раз в браузере).
4. Приложение у вас (и где угодно) в «Настройки → О программе и обновления» нажимает «Проверить обновления», видит список изменений, скачивает только нужное, ставит и перезапускается.

## Где хранить обновления — рекомендация: GitHub Releases
| Вариант | Плюсы | Минусы |
|---|---|---|
| **GitHub Releases** (рекомендую) | бесплатно, HTTPS, не нужен свой сервер, история версий, откат = «старый релиз», ссылка `…/releases/latest/download/latest.json` всегда ведёт на последний релиз | нужен аккаунт GitHub; чтобы программа скачивала обновления без пароля, репозиторий должен быть **публичным** — в релизах лежит только сама программа, не ваши данные |
| Свой сервер / облако (S3, VPS) | полный контроль, можно закрыть паролем | платно, нужно администрировать |
| Яндекс.Диск / Google Drive | просто | нет стабильных прямых ссылок, не подходит для автообновления |

Публичный репозиторий не раскрывает ваши ставки: база данных живёт только у вас в `%APPDATA%\DotaBets` и никуда не загружается.

## Однократная настройка
1. Зарегистрируйтесь на github.com → **New repository** (например, `dota-bet-tracker`, Public).
2. В приложении: Настройки → «Адрес обновлений» → вставьте `https://github.com/ВАШ_ЛОГИН/dota-bet-tracker`. Либо впишите этот адрес в `version.py` (`DEFAULT_UPDATE_URL`) перед сборкой.
3. Первый релиз: на странице репозитория **Releases → Draft a new release**, тег `v1.1.0`, перетащите все файлы из `release\1.1.0\`, нажмите **Publish release**.

## Как выпустить следующее обновление
1. Получите от меня новую версию проекта, в `version.py` будет новый номер (например, `1.2.0`).
2. `build_exe.bat` → `make_release.bat --notes "Что изменилось 1" --notes "Что изменилось 2"`.
   (Папку `release\1.1.0\` не удаляйте — по ней считается дельта.)
3. На GitHub: новый релиз с тегом `v1.2.0`, загрузить все файлы из `release\1.2.0\`.
4. Готово: у пользователей «Проверить обновления» найдёт 1.2.0 (при включённой автопроверке кнопка появится сама).

## Безопасность и откат
- **Данные отдельно.** База, настройки и копии — в `%APPDATA%\DotaBets`. Обновление меняет только папку программы.
- **Целостность.** Для каждого пакета проверяется размер и SHA-256, затем каждый файл новой версии сверяется с `latest.json`. Не сошлось — обновление отменяется, ничего не меняется. Если не подошла дельта — автоматически берётся полный пакет.
- **Только HTTPS**, защита от «zip-slip» при распаковке.
- **Резервные копии.** Перед установкой: копия базы (`..._before_update.db`) и копия папки программы (`updates\app_backup`).
- **Откат.** Скрипт установки после замены файлов запускает новую версию и ждёт отметки «запустилась» (файл `updates\started_ok.flag`). Нет отметки за 90 секунд или ошибка копирования — файлы возвращаются из копии, запускается старая версия. Журнал: `updates\update.log`.
- **Миграции базы.** Структура БД версионируется (`PRAGMA user_version`); новые версии добавляют миграции без потери данных. Если база новее программы, программа её не трогает и просит обновиться.
- **Ограничение.** Доверие строится на вашем аккаунте GitHub: кто может выкладывать релизы, тот может выпустить обновление. Включите двухфакторную защиту. В будущем можно добавить цифровую подпись `latest.json`.

## Что происходит с файлами после обновления
- Скачанные пакеты (`*.zip`, `*.part`) и папка распаковки удаляются после успешного запуска новой версии, а также при ошибке подготовки обновления.
- В `updates\app_backup` остаётся копия предыдущей программы (на случай ручного отката); перед следующим обновлением она заменяется свежей.
- Скрипт установки (`apply_update.bat`) использует `ping` вместо `timeout` и запускается скрытой консолью, поэтому окон не мигает.

## Адрес обновлений в настройках
Подойдёт адрес репозитория `https://github.com/ЛОГИН/РЕПОЗИТОРИЙ` или прямая ссылка на `latest.json`. Если вставить ссылку на страницу релизов (`…/releases`, `…/releases/latest`, `…/releases/tag/v1.1.0`), программа сама приведёт её к адресу репозитория и покажет, что исправила. Ссылка на тег всегда читается как «последний релиз».

## Версия установщика
`build_exe.bat` после сборки записывает версию из `version.py` в `installer\app_version.iss`, а `DotaBetTracker.iss` подключает этот файл. Вручную номер в установщике править не нужно.

## Установщик и права
Установщик (`installer\DotaBetTracker.iss`, Inno Setup) ставит программу в `%LOCALAPPDATA%\Programs\DotaBetTracker` без прав администратора, чтобы автообновление могло заменять файлы. Не устанавливайте программу в `C:\Program Files` — там замене файлов нужны права администратора.

## Что проверено, а что нет
Проверено автотестами (`tests/test_updater.py`): определение версии, дельта/полный пакет, подмена файла, повреждённый пакет, защита распаковки, интерфейс проверки. **Не проверено на реальном Windows:** сам скрипт замены файлов и перезапуска (`apply_update.bat`). Первое обновление проведите на копии: установите 1.1.0, выпустите 1.1.1 и проверьте процесс; журнал лежит в `%APPDATA%\DotaBets\updates\update.log`.
